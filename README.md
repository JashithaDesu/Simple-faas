# mini-faas

A Kubernetes-native FaaS platform built on raw primitives (CRD + custom controller),
not on Knative/OpenFaaS. See `/mnt/user-data/outputs/mini-faas-project-proposal.md`
for the full design rationale.

## Status: unverified skeleton

This code was written without network access, so it has **not been compiled or run**.
Treat it as a structurally correct starting point, not a tested build. Before you trust
it, run `go build ./...` on your own machine and fix whatever the compiler flags —
expect minor import/version mismatches against the exact k8s.io library versions
pinned in `go.mod`.

## What's real vs. stubbed

**Real, load-bearing logic:**
- `api/v1alpha1/function_types.go` — the CRD schema
- `internal/controller/function_controller.go` — the actual reconciliation loop:
  creates the Deployment, scales it based on idle timeout, writes status back
- `cmd/gateway/main.go` — cold-start detection, scale-up trigger, forwarding

**Deliberately left as next steps, not done for you:**
- `waitUntilWarm` polls every 250ms instead of using a proper watch — fine for a
  first working version, worth replacing once the core loop works, and worth
  mentioning in your evaluation write-up as a known limitation.
- No RBAC manifests (ClusterRole/ClusterRoleBinding/ServiceAccount) — the manager
  and gateway both need permission to read/write Function objects and Deployments.
  Kubebuilder normally generates these; write them by hand or run `kubebuilder init`
  once you have network access, then merge this code into that scaffold.
- No Deployment/Service YAML for the manager and gateway themselves — you need to
  build the two images, push them somewhere the cluster can pull from, and deploy
  them like any other app.
- No Prometheus metrics exporter yet — add a `/metrics` endpoint to the gateway
  once the core path works end to end.
- The deepcopy methods in `zz_generated.deepcopy.go` are hand-written, not
  generated by `controller-gen`. Regenerate them properly once you have network
  access (`make generate` in a real Kubebuilder project) — hand-written deepcopy
  is a common source of subtle bugs if the struct fields change later.

## Local setup (run this on your own machine, not in this sandbox)

```bash
# 1. Local cluster
kind create cluster --name mini-faas

# 2. Install the CRD
kubectl apply -f config/crd/function-crd.yaml

# 3. Build and load images into kind
docker build -f Dockerfile.manager -t mini-faas/manager:dev .
docker build -f Dockerfile.gateway -t mini-faas/gateway:dev .
kind load docker-image mini-faas/manager:dev --name mini-faas
kind load docker-image mini-faas/gateway:dev --name mini-faas

# 4. Deploy the manager and gateway (write Deployment/Service YAML for these —
#    intentionally not included, see "stubbed" list above)

# 5. Apply a sample function
kubectl apply -f config/samples/function-sample.yaml

# 6. Watch it work
kubectl get functions -w
kubectl describe function hello-function
```

## Suggested build order (matches the phases in the project proposal)

1. Get `go build ./...` passing locally — fix any dependency/version issues first.
2. Deploy just the manager + CRD, apply the sample Function, confirm a Deployment
   gets created and status updates — before touching the gateway at all.
3. Add RBAC so the manager can actually read/write Deployments in-cluster.
4. Bring up the gateway, wire real cold-start end-to-end.
5. Add metrics, then the AWS deployment, per the proposal's phase list.
